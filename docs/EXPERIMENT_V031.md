# 0.3.1 开发回归计划

本计划在补跑请求之前保存。0.3 的 8 案例、32 次尝试已完整结束，共 100 次 API 请求；原始分数及源码已导出到 `eval/results/v03/`。此前开发联调用了 7 次请求，本轮至此累计 107 次。

复核发现两项需修正的实现/任务定义问题：

1. 数值规则将明确否定 p95 相加的句子误判为违规。修复否定范围，加入真实原句及对照测试，版本升为 1.0.1；不重新写入旧实验分数。
2. 模型将“配置缩小池上限，引起连接池耗尽”选为泛化的 `bad_configuration`。增加通用类别定义，明确 cause_code 表示观测到的失败机制，触发因素另述；池耗尽优先于配置这一更泛化的触发类别，依赖 deadline 超时同理。

定向回归只使用早已参与开发的 inc001，运行 single-shot、react、investigator 各一次，两个 Agent 分别最多 6 轮，工具上限 32。理论上限 `1 + 6 + 6 = 13` 次请求，与前面 107 次合计不超过 120。不得把本次回归混入此前 32 次实验、挑选更好的结果替换失败、或宣称在未见案例上验证了提升。

零模型请求的旧轨迹回放只检验审计器误报修复。即使新调用成功，也只能支持这一个已知开发场景的定向回归。压力集的证据组争议及遗漏语义检查继续保留在事后审阅文档中。
