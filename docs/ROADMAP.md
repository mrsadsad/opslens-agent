# OpsLens 求职交付标准

目标是证明你能把 Agent 从模型调用推进到可验证、可恢复、可比较的系统。现已完成真实本机故障采集、两类 Agent 策略、两类固定对照、工作台、MCP 与统计评测，并执行了 8 个案例 × 4 策略的真实模型实验。结果及评分争议见 [实验报告](EXPERIMENT_RESULTS_V03.md)，尚无生产或大规模独立泛化证据。

## 尚缺的关键成果

1. **更充分的真实模型实验。** 已完成 32 次小规模对照，保留全部尝试、失败、用量和延迟。下一步应验证更广泛的任务，而非从本轮少量样例推出泛化准确率。
2. **独立数据。** 当前样例和本机实验都为开发数据。需扩充拓扑、故障组合及独立采集批次，再冻结测试协议。公开数据接入须核对许可证和任务定义。
3. **一个成立的优化结论。** 本轮已发现复杂策略未普遍占优、误报和类别定义影响评分。继续检验何时需要动态调查，不能靠堆模块或改标签制造提升；无提升、成本上升和局部退化均保留。
4. **个人负责的技术工作。** 独立分析一次失败、实施改进、运行对照并解释结果。当前 AI 协助搭建的部分不能包装成未经辅助的独立成果。

## 第一项研究问题

当近期变更与真正根因不一致时，显式要求反证是否能降低误诊？代价是多少额外调用与错误弃权？当前 inc006 只用于开发验证，有效结论还需要独立生成的真实或公开案例。

先用一个真实快照联调两类 Agent，再做完整比较。预先确定每个条件的回合、观测预算和总调用上限，避免早运行的策略耗尽预算，后续条件全部缺测。

## 投递材料验收

- 可复现仓库：配置、数据来源、运行方式、已知限制。
- 三到五分钟演示：实际故障、真实模型调查、一次失败及定位过程。
- 实验报告：数据划分、版本、样本数、重复次数、预算、对照、误差范围与失败类别。
- 技术复盘：至少两项可辩护的决定及替代方案。
- 真实简历：明确个人贡献和实测数字，不把本机实验写成生产规模。

简历结构可以是：

> 开发服务故障调查 Agent，构建本机故障注入及恢复环境，设计（你负责的机制）并实现可恢复工具执行与证据审计；在（来源、任务数、划分）上比较（对照条件），取得（真实指标）并分析（失败类别与代价）。

这些材料对齐 Agent 应用与后端工程；录用仍取决于具体岗位、资格、编码基础和面试表现。
