# 0.3 预先确定的联调与对照协议

本协议在本轮真实模型请求之前保存。目标是补充项目的效果证据，检验工具能力提示与数值风险反馈是否能支撑可用的调查流程；不预设 Investigator 必须获胜。

## 改动与验收

1. 查询只接受该服务、记录类型实际支持的阶段；不支持时明确反馈，不默默扩大查询。工具公开能力从观测数据生成，不使用标签。
2. 对减半比例矛盾、错误数量与百分比混用口径、p95 相加等已知风险做有边界的规则检查。问题报告要求修正或说明不确定性；保留被拒绝的原始提交。规则不是全面语义验证器。
3. 单次评分与批量清单共享标签；根因组件参与评分，替代证据按组满足即可，不要求穷举同义证据。
4. 旧真实报告重新评分，保留旧分数并另存新版结果，不能改写历史输出制造改善。

开发联调后的调整（正式对照前）：inc001 在 8 步上限内用 7 次请求完成，11 次查询中 2 次为空，总用量 28,037 token。为让模型知晓正式实验的 6 步限制，正常与压缩上下文均加入剩余调用/工具预算以及预留提交回合的提示。此调整只依据已使用的开发案例，未查看新压力案例内容或结果。正式对照仍采用原先预定的 6 步上限，不增加模型调用预算；联调与正式对照使用的源码摘要分别保留。

## 模型预算

本轮最多 120 次真实 API 请求，不包含软件测试或本机 HTTP 负载。

- 开发联调：inc001 / Investigator，最多 8 次模型请求，32 次工具调用。
- 正式小规模对照：8 个案例 × 4 策略，每种一次。两种固定策略各 1 次模型请求，ReAct 和 Investigator 各最多 6 次；合计理论上限 `8 × (1 + 1 + 6 + 6) = 112` 次请求。
- 内置 HTTP 自动重试关闭，失败请求计入预算；不挑选最好的重试。模型为本机配置的 DeepSeek，具体身份和代码摘要在请求前写入 experiment.json。
- 预算是请求次数限制，不是金额保证；token 阈值和最后响应越界边界沿用评测说明。

## 数据与解释范围

8 个案例包括两个现有合成开发样例（inc001、inc006）、两个本次采集的本机 HTTP 故障（池耗尽、依赖超时，seed 41）以及四个新编制的合成压力案例。不同来源、不同划分分别汇总，不合成一个“总体准确率”。

压力案例在本轮实现过程中由另一协作代理编制，运行前冻结哈希。主实现代理在冻结代码前不检查具体内容，但编制者知道项目任务和类别；这不是第三方公开基准，也不能宣称完全独立盲测。查看结果后，这一版本就视为已使用的回归集。

比较 single-shot、fixed-workflow、react、investigator，源数据、观测预算、提交检查相同；检索方法和可修复回合有意不同。固定单次策略没有免费修复回合，不能将差异全部归因于假设记录。

所有安排的尝试、失败、用量、时延、空查询和不支持阶段查询均保留。报告给出每个案例的结果及失败原因；小样本区间仅作探索性描述，不作大规模泛化结论。

## 投递前应具备的材料

一个可复现的真实模型对照实验；一个已复现并修复的失败类别；可检查的原始轨迹与计分口径；对已知限制和个人负责模块的解释。达到这组可检查的里程碑后准备重点岗位投递，不以“所有优化空间消失”为条件。
