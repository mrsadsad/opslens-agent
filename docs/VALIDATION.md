# OpsLens 验证记录

本记录区分软件验证、实际故障实验和模型效果。验证环境为本机 Windows / Python 3.12.3，日期 2026-10-01。当前实现为 0.3.1；历史实验按当时版本保留，不覆盖原始输出或分数。

## 0.3 完整对照与 0.3.1 修复

已完成 8 个案例 × 4 种策略的 32 次真实 DeepSeek 尝试，正式实验共 100 次 API 请求。合成开发、本机 HTTP 测量、新编制压力案例分别汇总，不把重复策略当作独立故障。结果未证明复杂策略普遍占优；已知返回用量为 468,960 token，有一次响应协议失败导致用量不完整。

完整结果、冻结源码、逐次失败和评分争议见 [实验报告](EXPERIMENT_RESULTS_V03.md)、[可审阅产物](../eval/results/v03/README.md)。数值审计器补充了历史报告的部分风险检查，也暴露了否定句误报；0.3.1 修复此误报并澄清根因机制类别。随后 3 次已知案例定向回归使用 11 次请求：两种 Agent 自动检查通过，single-shot 的实际比例矛盾被拒绝；通过的报告仍有语义问题。回归 [单独记录](../eval/results/v031-regression/README.md)，不用于替换原成绩。

## 0.2 首次真实模型联调（历史）

使用 `.env` 配置的 DeepSeek Key 执行，模型为 `deepseek-flash`，关闭思考模式，每次输出最多 4096 token：

```powershell
python -m opslens run --policy investigator --case data/cases/inc001.json --max-steps 12 --max-tools 24 --max-tokens 24000
python -m opslens evaluate runs/66ac5a39a7854edaa0572d3b61c18db6/result.json --output runs/66ac5a39a7854edaa0572d3b61c18db6/evaluation.json
```

- Run：`66ac5a39a7854edaa0572d3b61c18db6`，状态 `completed`；数据为合成开发案例 `inc001`。
- 实际发出 7 次模型请求，无重试；19 次工具调用包括 16 次查询、2 次假设记录和 1 次诊断提交。累计模型调用耗时约 10.97 秒。
- API 返回输入 20,396、输出 2,248、合计 22,644 token，`usage_complete=true`。这是用量记录，不是金额估算。
- 根因类别 `connection_pool_exhaustion` 与标签相符；3 条必需证据全部覆盖，6 条引用全部可追溯。报告把根因服务定位为 `checkout`，符合案例内容；该案例标签未包含服务字段，因此服务定位未计入自动评分。
- 模型用数据库正常指标和无变更记录反驳依赖侧超时假设。部分带 `phase` 的查询没有结果，模型随后去掉过滤条件取得证据。

**自动评分通过不等于解释完全正确。** 核读输出发现：将连接池 100→20 写成“砍半”（实际减少 80%）；把一分钟 172 条错误直接称为与 18% 错误率一致（按 240 请求/秒计算约 1.19%，且统计口径未确认）；将不同指标的 p95 作加法解释总延迟，也缺少请求级证据。这些问题未被当时的结构与引用评分器捕获。0.3 增加了有限数值规则，并在旧输出回放中检出这三类风险，但规则不保证完整语义正确。原始模型报告和轨迹保留，复核意见另存于该运行目录的 `review.md`，未改写原始输出。

本次证明该配置可完成真实 API、原生工具调用、竞争假设、报告导出和离线评分流程；不证明四种策略的优劣、语义论证正确率或未见场景泛化。运行产物位于已忽略的 `runs/`，重新执行会产生不同运行 ID 和结果。

## 实际故障实验

执行：

```powershell
python -m opslens lab --suite --seeds 17 23 --output runs/verification-lab
```

八个实验各运行三个阶段，每阶段 24 个负载请求。本次所有 baseline 与 recovery 都是 0/24 错误，实验服务器均关闭。故障阶段观测如下：

| 场景 | seed 17 错误请求 | seed 23 错误请求 | 观测解释 |
| --- | --- | --- | --- |
| healthy | 0/24 | 0/24 | 无操作对照维持正常 |
| pool_exhaustion | 21/24 | 20/24 | 并发槽池收缩后获取超时 |
| dependency_timeout | 24/24 | 24/24 | 下游处理延迟超过调用端 deadline |
| bad_configuration | 24/24 | 24/24 | 错误 URL 路径导致实际 HTTP 404/502 |

这些数字是实验环境的故障与恢复测量，**不是 Agent 诊断效果**。线程调度会影响再次运行的具体计数和延迟；验收使用宽松质量门槛，不要求复现相同毫秒值。

本地审计清单为 `runs/verification-lab/manifest-7bd05ab0e2244290803208f5f5e07322.json`，SHA-256 为 `97a1eaef115f4dfb9b4c584f0e92f109f8c05144b435f9cbf0d114f05013dfd5`。该运行目录已被 Git 忽略；重新执行上述命令会生成新 ID、时间和哈希。每次实验的 requests.jsonl 与 provenance.json 支持复算指标和追查实际配置。

`benchmark --dry-run` 已分别验证六个合成开发样例和八个本机测量快照。两者分开标记数据来源；所有样例均属于 dev，四个故障模板不是八个独立故障类型。

## 审查修复

- 压缩上下文中的空索引字段曾使输出超过字符上限；现在所有字段都计入预算。
- 压缩曾遗漏最近工具错误；现在保留结构化错误反馈，便于模型修复调用。
- 最终失败请求曾遗漏 HTTP 尝试数；现在记录已知次数，未知计数明确标记。
- 中断或总预算耗尽造成的缺测不再生成可误读的成功率区间。
- 实验中途模型身份变化会使实验失效、停止后续调用，并撤销对比区间。
- 固定脚本不支持 Investigator 时，服务在创建任务前明确拒绝。
