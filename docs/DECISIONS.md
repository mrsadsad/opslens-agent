# OpsLens 技术取舍

## 显式循环和策略对照

用 Python 标准库实现原生工具调用，便于检查状态、预算与恢复边界。React 和 Investigator 共用工具及模型接口，差异由定义哈希记录。后续若需要分布式执行或复杂编排，应比较成熟框架的维护收益。

假设与反证记录是待验证的工程假设。它可能提高调查完整性，也可能增加调用与错误弃权，因此保留三个对照。门控验证来源、结构及有限的数值风险，不自动证明语义。

## 故障实验与答案隔离

先运行实际 HTTP 负载，再从请求计算观测。标签在故障及恢复门槛通过后才生成，存于工具不可读取的控制面。信号量池模拟客户端资源，不替代真实数据库或大规模系统。

工具能力从观测记录计算，按服务说明可查类型、阶段和结构化 trace。指定不可用阶段时返回 `unsupported_phase` 与可用选项，要求模型显式修正查询；不默默放宽范围，以免将其他阶段的数据误当目标阶段。未带阶段字段的旧快照仍支持不指定阶段的查询。这一设计针对实际调查中的无效阶段过滤，不能保证模型不再发出空查询。

## 精确证据压缩

超出字符预算时，保留任务和假设，重新装配带 ID 的已观察记录，不让摘要模型改写证据。完整历史留在 SQLite，遗漏证据可回取。0.4 根据最近工具事件优先保留刚返回的证据，再考虑假设引用、服务能力与历史；同一 ID 被回取时不会因字典插入顺序仍旧而继续被忽略。可见、省略、未能列入索引的数量均明确披露；预算过小时仍可能省略内容。记录本身的 1600 字符截断是另一层边界，不能把回取描述为读取任意长度全文。

普通上下文也逐次附带剩余调用预算和提交提示，不必等压缩后才让模型知道限制。提示计入上下文字符预算，实际限额仍由运行时执行；提示不是规划能力的保证。

## 有限数值门控

采用可复核的确定性规则检查明确数值变化、分母与统计口径、p95 相加等已知风险，不引入模型自评分。所有策略的最终报告使用同一门控，调查假设也检查数值陈述。Agent 可消耗剩余预算修正，一次调用对照没有额外重试；比较需连同调用与修正成本解释。

这些规则覆盖有限且可能产生需复核的提示，不是通用数学或因果验证。保留 `numeric_rejection_count`，让最终报告修正成功后仍能看到历史问题；无最终报告时不能把数值检查记成通过。审计版本与源码摘要进入运行定义，规则变更后不能悄悄复用旧检查点。

## 检查点语义

事务与版本号防止旧状态覆盖新状态。请求前扣减步数并记录 pending；中断请求用量未知时标记不完整。只读查询至少执行一次，同一 run 暂无分布式租约保证。

## 公平评测

各策略可访问相同源并有相同累计观测限制，固定对照使用不同检索规则。全局模型预算在调用前扣减，评测时关闭内部 HTTP 重试。故障模板按组统计，换 seed 和重跑不代表新故障泛化；语义正确性仍须人工审阅。

标签同时支持全部必需的 `required_evidence` 和 AND-of-OR 的 `evidence_groups`：每组覆盖一条替代证据，且每组都覆盖。两者都只认可已观察并引用的 ID，避免把可替代日志误设成必须全取，也避免只引用一个信号便拿到全部证据分。标签只供评价使用。

## 服务与协议

浏览器只提交白名单 case_id，不能读任意路径。工作台仅绑定回环地址，队列有界；同源校验不等于生产认证和多租户隔离。MCP stdio 复用工具契约，负责互操作，不负责模型决策和评测。

工作台支持合成快照及 `local_fault_lab` 的真实本机采集，并展示数值风险；本机测量不等于生产事故。超限请求先返回 413 并声明 `Connection: close`，随后用有界字节数和短时限排空请求正文再关闭连接，兼顾 Windows 连接复位问题与拒绝请求的资源上限。

## 修复边界

Agent 仅产生待人工验证的建议。实验故障撤销由控制器负责，不能算 Agent 自动修复能力。未来加入修复必须另行实现预览、授权、幂等执行、验证与回滚。
